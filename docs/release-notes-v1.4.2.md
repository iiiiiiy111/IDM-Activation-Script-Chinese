# v1.4.2 发布说明 — 上线前的稳定性与可维护性补强

- 发布日期：2026-07-28
- 类型：缺陷修复 + 发布流程加固（**激活 / 冻结 / 重置 / 更新开关的逻辑一行未动**）
- 上一版：[v1.4.1](./release-notes-v1.4.1.md)（发布包改用固定文件名）

## 一句话总结

这一版没加任何新功能，只做一件事：把「文档写了、实现却对不上」的几处缺口补齐，并给发布流程装上自动守卫，让「改了脚本忘了重新打包」不再悄无声息。

## 修了什么

### 1. 日志文件名一直是无效的

`IAS.cmd` 里生成日志文件名的那几行原本写在 `if (...)` 代码块内：

```cmd
if %_log%==1 (
set "_logstamp=%date%_%time%"
set "_logstamp=%_logstamp::=%"      REM <- 这里的 %_logstamp% 取不到上一行的值
...
set "log_file=%log_dir%\IAS-%_logstamp%.log"
)
```

CMD 会在**整块解析时**一次性展开块内所有 `%var%`，此时 `_logstamp` 还没被赋值，展开结果是字面量。后果是所有静默运行产生的日志都叫 `IAS-%_logstamp%.log`，时间戳完全失效，多次运行全部追加进同一个文件。

现在改由 `:init_log` 子程序逐行执行（子程序里每行独立解析，`%var%` 能拿到最新值）。CI 加了回归断言：日志文件名里出现 `_logstamp` 字面量就直接失败。

### 2. `/log=路径` 文档承诺了但没实现

README、`使用说明.txt`、`ARCHITECTURE.md`、维护清单四处都写着 `/log=路径`，但参数解析只认不带路径的 `/log`。用户照文档传路径，日志会被静默写到 `%SystemRoot%\Temp`，去指定位置找不到，只会认为脚本坏了。

根因有点隐蔽：原来的参数解析是

```cmd
for %%A in (%_args%) do (
  if /i "%%A"=="/log" set _log=1
)
```

而 `for %%A in (...)` 的集合解析除了空格，**还把逗号、分号和等号当分隔符**——`/log=C:\x.log` 在循环里早就被拆成 `/log` 和 `C:\x.log` 两个 token，比较永远只能拿到 `/log`。所以路径提取不能挂在这个循环里，现在改成在循环外从完整参数串中取。

行为约定：

- `/log`（不带路径）→ 写到 `%SystemRoot%\Temp\IAS-<时间戳>.log`，脚本启动时会把完整路径打印出来；
- `/log=路径` → 写到指定文件，目录不存在会自动创建，写不进去会提示并回退默认位置；
- `/silent` 会自动开启日志；
- **路径不能含空格**（参数按空格切分）。

### 3. `开始激活.cmd` 提权时把参数丢了

非管理员启动时走 `Start-Process -Verb RunAs` 提权，但没有传 `-ArgumentList`：

```cmd
powershell -NoProfile -Command "Start-Process -FilePath '%self%' -Verb RunAs"
```

用户跑 `开始激活.cmd /frz /silent`，提权后的窗口弹出的却是交互菜单。同时补了引号处理：路径和参数里的单引号按 PowerShell 规则转义成两个单引号（含 `'` 的目录如 `D:\Tom's Tools\` 不再让提权语法出错），参数里的双引号在拼进 `-Command "..."` 之前先剥掉。

### 4. 失败时不告诉用户备份在哪

激活/冻结/重置流程结束时（**包括失败退出**）现在会显示本次注册表备份的文件名模式和日志路径；没开日志且退出码非 0 时，会提示可加 `/log` 重跑取证。以前失败了只能去翻文档猜路径。

## 发布流程加固（维护侧）

发布包用的是固定文件名 `IDM-Activation-Script.zip`，好处是下载链接一次写死，代价是「只改了仓库、忘了重新打包」**没有任何征兆**——用户下载到的还是旧脚本，而 CI 一路绿灯。

这一版把这条路堵上：

- **`tools/verify-release.ps1`**（CI 必过）：校验 `.sha256` 与实际哈希一致；包内会被执行的文件（`IAS.cmd` / `开始激活.cmd` / `使用说明.txt`）与仓库逐字节一致，不一致直接失败；文档类文件不一致只告警；`iasver` 与 `CHANGELOG.md` 顶部版本号一致。
- **`tools/pack-release.ps1`**：把打包变成一条可重复的命令（固定清单、GBK 条目名、自动重算 SHA256）。CI 每次都会跑一遍并把结果作为 `release-bundle-rebuilt` artifact 上传，没有 Windows 的维护者可以直接下载使用。
- **CI 冒烟扩容**：新增 `/act`、`/frz` 未装 IDM 时应返回 `1` 的探针，以及 `/log=路径` 产出文件、默认日志文件名带真实时间戳两条断言。
- **`.gitattributes` 补规则**：`*.zip binary`、`*.sha256`、`*.ps1`，以及 `LICENSE text eol=lf`。`LICENSE` 没有扩展名，原来不匹配任何规则，Windows 上 `core.autocrlf=true` 会把它重写成 CRLF，导致同一份提交在不同机器上打出的发布包字节不同。

守卫上线后立刻抓到了真实问题：当时 `release/` 里的包，三个运行时文件都还停留在改动前的版本，README 更是落后了四次文档提交。本版的发布包已重打并逐文件核对过。

## 没改什么

- 激活 / 冻结 / 重置 / 禁用更新 / 恢复更新的逻辑**一行未动**，行为与 v1.4.1 完全一致；
- 菜单编号、参数、退出码语义都不变（`/log=路径` 从「写了不生效」变成真的生效，属于修复而非行为变更）；
- GBK 编码、CRLF 行尾、文件末尾空行等约束不变。

## 升级建议

- **无人值守用户建议升级**：`/log=路径` 现在才真正可用，日志文件名也才有意义；带参数走 `开始激活.cmd` 的用法在这一版之前会静默丢参数。
- **只用图形菜单的用户**可以不急：菜单行为完全没变，升级带来的只是失败时多打印备份和日志路径。

校验命令（PowerShell）：

```powershell
Get-FileHash .\IDM-Activation-Script.zip -Algorithm SHA256
```

与 `IDM-Activation-Script.zip.sha256` 内的值比对一致后再解压使用。
